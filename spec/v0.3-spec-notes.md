## 1. Epistemic Hierarchy & Governance Constraints

```
 Raw Evidence ──► Annotator Observation ──► Independent Annotation ──► Reliability Analysis ──► Optional Adjudication
(Logs/Playback)       (Visual Rules)             (Locked Record)          (κ_sub, Gwet's AC1)     (Adjudicated Dataset)
```

> [!IMPORTANT]
> **Core Epistemic Principles:**
> 1. **Epistemic Hierarchy:**  
>    $$\text{Instrumentation} \neq \text{Measurement} \neq \text{Validation} \neq \text{Theory}$$
> 2. **Construct Scope Boundary:**  
>    *$E_c$ is a proposed measure of digital system coordination overhead. It is NOT currently a general theory or measurement of human cognition, consciousness, intelligence, attention, or mental entropy.*
> 3. **Reliability vs. Validity:**  
>    *A reliable annotation protocol does not establish that the annotated construct exists as theorized; it establishes only that the operational procedure can be applied consistently under specified conditions.*
> 4. **Observational vs. Causal Attribution:**  
>    *Annotators observe system presentations and behavioral trajectories; they do not observe underlying internal causality.*
> 5. **Adjudication vs. Ground Truth:**  
>    *Adjudication does NOT create scientifically validated ground truth labels. `final_resolution` is an adjudicated dataset consensus for benchmark comparison, not an objectively correct or validated label.*
> 6. **Reconstructible Audit Trail:**  
>    *The audit trail must make it possible to reconstruct why a rating was assigned without treating the rating itself as raw evidence or scientific ground truth.*

## 2. Observational (Non-Causal) Rubrics

### 2.1 Decision Overhead ($D$) Observational Rubric

* **Unit of Analysis:** Discrete decision point presented on screen (e.g., dialog, dropdown, form submit, menu pick).
* **Prerequisite:** Declared Task Intent ($I_{\text{task}}$) must be established *prior* to recording and made visible to the annotator.

| Rating Category | Observational Criteria (What is Seen) | Example Screen Artifact |
| :--- | :--- | :--- |
| `INTENT_INTRINSIC` | Decision choice directly specified by or inherent to the declared task objective $I_{\text{task}}$ (e.g., selecting export file format, choosing target budget value). | User picks "PDF" when $I_{\text{task}}$ explicitly specifies "Export report as PDF". |
| `SYSTEM_PRESENTED` | Decision point presented or required by the digital system during execution that is **not** specified by the underlying task objective $I_{\text{task}}$. | Interface prompts user to pick an OAuth provider, IAM role, region zone, or workspace. |
| `DUAL_OR_CONTEXT_DEPENDENT` | Decision point that is system-mediated but serves a legitimate dual role in advancing the task (e.g., authentication method required for cloud access). | Authentication modal where access is required, but provider selection is system-structured. |
| `INSUFFICIENT_EVIDENCE` | Screen recording or log trace lacks context to determine whether the decision was specified by $I_{\text{task}}$. | Missing prompt text, truncated video segment, or unrecorded modal. |

### 2.2 Intent Deviation ($N$) Observational Rubric

* **Trajectory Categories:**

| Rating Category | Observational Criteria | Example Behavioral Artifact |
| :--- | :--- | :--- |
| `DIRECT_INTENT_PROGRESSION` | Observed action/episode directly advances the declared linear path toward $I_{\text{task}}$. | Typing code directly in target file, filling target web form without backtracking. |
| `INDIRECT_OR_DETOUR_BEHAVIOR` | Observed action/episode deviates from the direct path (e.g., opening help documentation, opening search, menu backtracking, error dialog recovery). | User opens documentation tab, searches CLI syntax, returns 30s later to execute command. |
| `TASK_DISCONNECTED_BEHAVIOR` | Observed action/episode switches focus to applications or web domains completely outside the task ontology. | Focus switch to personal social media app or unrelated entertainment video. |
| `INSUFFICIENT_EVIDENCE` | Trace/recording lacks sufficient visual or log context to establish trajectory status. | 45-second idle gap with no input events and static screen recording. |

## 3. Multi-Rater Data Schema & Technical Immutability

### 3.1 Technical Immutability Rules
- Initial independent ratings (`initial_ratings`) are stored as frozen, immutable tuple objects (`@dataclass(frozen=True)`).
- Attempts to modify, reassign, or delete attributes of `initial_ratings` after creation will raise a runtime `FrozenInstanceError` / `TypeError`.
- Post-rating adjudication metadata is stored in a separate, explicit `AdjudicationRecord` that references the immutable initial ratings without mutating them.

## 4. Dual Reliability Mathematics ($\kappa_{\text{substantive}}$, $\kappa_{\text{evidence}}$, Gwet's AC1)

### 4.1 Cohen's Kappa ($\kappa$) — Two Annotators
For two independent annotators assigning $N$ items into $K$ mutually exclusive categories:

$$\kappa = \frac{P_o - P_e}{1 - P_e}$$

Where $P_o = \frac{1}{N} \sum_{k=1}^K n_{kk}$ and $P_e = \sum_{k=1}^K p_{1k} \cdot p_{2k}$.

Large-sample standard error:
$$\text{SE}(\kappa) = \frac{\sqrt{P_o (1 - P_o)}}{(1 - P_e) \sqrt{N}}$$

### 4.2 Fleiss' Kappa ($\kappa_F$) — Multiple Annotators ($m > 2$)
For $m$ annotators rating $N$ items across $K$ categories:

$$\kappa_F = \frac{\bar{P} - \bar{P}_e}{1 - \bar{P}_e}$$

Where $P_i = \frac{1}{m(m-1)} \left( \sum_{k=1}^K n_{ik}^2 - m \right)$, $\bar{P} = \frac{1}{N} \sum_{i=1}^N P_i$, $p_k = \frac{1}{N m} \sum_{i=1}^N n_{ik}$, and $\bar{P}_e = \sum_{k=1}^K p_k^2$.

### 4.3 Gwet's AC1 Statistic ($AC_1$)
To diagnose prevalence paradoxes where high observed agreement $P_o$ yields artificially depressed $\kappa$:

$$AC_1 = \frac{P_o - e_\gamma}{1 - e_\gamma}$$

Where $e_\gamma = \frac{1}{K - 1} \sum_{k=1}^K \pi_k (1 - \pi_k)$, and $\pi_k = \frac{p_{1k} + p_{2k}}{2}$.

### 4.4 Separate Evidence & Substantive Statistics
1. **$\kappa_{\text{substantive}}$:** Calculated strictly on items where **both** annotators selected a substantive category (excluding `INSUFFICIENT_EVIDENCE`).
2. **$\kappa_{\text{evidence}}$:** Binary agreement calculation on whether the item provided sufficient evidence (`SUFFICIENT` vs `INSUFFICIENT_EVIDENCE`).
3. **Prevalence Report:** Category frequencies and proportion of insufficient-evidence items reported separately.
4. **Governance Threshold:** $\kappa_{\text{substantive}} \ge 0.80$ (preregistered project gate threshold).

## 5. Granularity Multi-Criteria Evaluation ($N$)

When evaluating whether Intent Deviation ($N$) should be annotated at the **Event**, **Action**, or **Episode** level, the decision must be evaluated across six weighted criteria:
1. **Inter-Rater Reliability ($\kappa_{\text{substantive}}$)**
2. **Theoretical Coherence** (alignment with goal-directed behavior)
3. **Temporal Meaning** (preservation of meaningful duration/boundaries)
4. **Evidence Requirements** (feasibility of observational verification)
5. **Category Prevalence** (avoiding extreme category skew)
6. **Reproducibility Across Annotator Cohorts**

---

## 6. Annotator Training & Information Access Matrix

- **Declared Task Intent ($I_{\text{task}}$):** Explicit statement of task goal established *prior* to session recording.
- **Annotator Information Access:** Annotators see screen recording, telemetry event stream, window titles, and $I_{\text{task}}$. Annotators CANNOT see each other's ratings.
- **Training Qualification:** Trainees must achieve $\kappa \ge 0.80$ on a 10-session calibration practice set (permanently excluded from evaluation datasets).
